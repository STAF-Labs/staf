# ADR 0003: Формат импорта типов контента

## Статус

Предложено

## Дата

2026-07-31

## Контекст

В админке STAF появилась страница `Типы контента` и отдельная страница импорта из файла. Тип контента является базовым справочником: например `Мод`, `Карта`, `Текстура`, `Плагин`.

Связка типа контента с конкретной игрой хранится отдельно в `game_content_types` и должна настраиваться в форме игры. Поэтому импорт на странице типов контента не должен одновременно создавать game-specific связи, dimensions или значения dimensions.

Нужно заранее определить формат CSV/Excel файлов, чтобы UI, backend-валидация и будущий импорт работали одинаково.

## Проблема

Нужно выбрать понятный и стабильный формат файла для массового создания `content_types`, который:

- поддерживает CSV и Excel;
- не требует ручного ввода `slug`;
- не смешивает базовый справочник с настройками конкретной игры;
- допускает простой импорт без сложного маппинга колонок;
- остается расширяемым для будущего preview/validation flow.

## Принятое решение

Импорт типов контента принимает табличный файл с первой строкой-заголовком.

Поддерживаемые форматы:

- `.csv` в UTF-8;
- `.xlsx` как основной Excel-формат.

Формат колонок:

| Колонка | Обязательная | Описание |
| --- | --- | --- |
| `name` | Да | Название типа контента, до 64 символов. |
| `is_public` | Нет | Публичность. Если пусто, используется `true`. |

`slug` не передается в файле. Backend генерирует его автоматически через существующий `HasSlug`.

Допустимые значения `is_public`:

- `true`, `false`;
- `1`, `0`;
- `yes`, `no`;
- `да`, `нет`;
- пустое значение как `true`.

Пример CSV:

```csv
name,is_public
Мод,да
Карта,true
Текстура,1
Плагин,нет
```

Импорт этой страницы создает или валидирует только записи `content_types`. Привязка к играм через `game_content_types`, notes и dimensions не входят в этот формат.

## Рассмотренные варианты

### Вариант 1: Импортировать только базовые content_types

Файл содержит только `name` и `is_public`.

Плюсы:

- формат простой для пользователя;
- не смешивает справочник и настройки конкретных игр;
- легко валидировать и показывать ошибки построчно;
- новый тип контента виден сразу, даже если еще не привязан к игре.

Минусы:

- после импорта типы нужно отдельно привязать к играм.

Причина выбора:

- это соответствует текущей модели: `content_types` отдельно, `game_content_types` отдельно.

### Вариант 2: Импортировать content_types вместе с колонкой game

Файл содержит `name`, `is_public`, `game`.

Плюсы:

- можно сразу создать привязки к играм.

Минусы:

- нужен поиск игры по имени или slug;
- появляются конфликты и неоднозначности;
- импорт начинает изменять `game_content_types`, хотя страница отвечает за `content_types`;
- позже сложнее добавить dimensions без разрастания формата.

Причина отказа:

- формат смешивает два разных уровня настройки контента.

### Вариант 3: Сделать гибкий маппинг колонок

Пользователь загружает файл с любыми заголовками, а UI предлагает сопоставить колонки.

Плюсы:

- удобно для файлов из разных источников;
- меньше требований к подготовке файла.

Минусы:

- заметно сложнее UI и backend;
- преждевременно для небольшого справочника;
- больше сценариев ошибок.

Причина отказа:

- сейчас достаточно фиксированного формата с понятной подсказкой.

## Последствия

Положительные последствия:

- формат легко объяснить на странице импорта;
- backend может валидировать файл построчно;
- `slug` остается внутренней ответственностью backend;
- импорт не ломает границы между `content_types` и `game_content_types`.

Отрицательные последствия и компромиссы:

- нельзя одним файлом сразу настроить типы контента для игр;
- старый Excel `.xls` не является целевым форматом на первом этапе.

Что нужно учесть в будущем:

- добавить preview перед сохранением;
- показывать ошибки по строкам;
- определить стратегию дублей: пропускать, обновлять или считать ошибкой;
- при необходимости сделать отдельный импорт связок `game_content_types`.

## Влияние на код

Нужно учитывать:

- backend endpoint импорта для `content_types`;
- request validation для файла и строк;
- сервис разбора CSV/XLSX;
- Vue admin page `ContentTypesImportView`;
- тесты happy path, неверных заголовков, дублей и некорректного `is_public`.

Migrations и модель `ContentType` менять не требуется.

## Связанные внешние пакеты

Потенциально потребуется пакет для чтения `.xlsx`, например `openspout/openspout`.

Для CSV внешний пакет не нужен.

## Примечания

Если позже понадобится импорт привязок к играм, его лучше делать отдельным форматом, например для `game_content_types`, а не расширять этот файл колонкой `game`.
