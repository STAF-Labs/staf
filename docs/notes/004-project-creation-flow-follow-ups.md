# Доработка flow создания проекта

Статус: требуется доработка.

Текущий API и многошаговый интерфейс создают проект по основному сценарию, но перед завершением flow
нужно устранить следующие ограничения:

- вынести создание проекта, media и project-level dimensions в единую бизнес-операцию с откатом и
  очисткой файлов при ошибке;
- назначать начальный статус проекта на backend, не принимая произвольный статус от клиента;
- добавить policy/permissions на создание проекта и определить роли, которые могут создавать проект
  от имени организации;
- добавить `licence_name` в таблицу, модель, API, frontend и итоговое превью;
- сделать `summary` обязательным на backend и проверять содержимое `summary` и `description`, а не
  только тип JSON;
- ограничить общий размер multipart-запроса и настроить throttle для загрузки файлов;
- определить и проверить правило выбора конечных значений иерархических dimensions;
- возвращать `dimension_value_ids` единообразно после создания и при последующем получении проекта;
- расширить feature-тесты сценариями прав, статусов, ролей организации, некорректных файлов,
  пустых документов и сбоев с откатом.

Дополнительный функционал после стабилизации основного flow — серверное сохранение незавершенного
мастера и возможность продолжить его позднее. Предлагаемая архитектура описана в
[`ADR 0006: Серверные черновики создания проектов`](../adr/0006-project-creation-drafts.md).
