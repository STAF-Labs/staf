# Доработка flow создания проекта

Статус: требуется доработка.

Текущий API и многошаговый интерфейс создают проект по основному сценарию, но перед завершением flow
нужно устранить следующие ограничения:

## Выполнено

- начальный статус проекта назначается на backend и не принимается от клиента при создании;
- `licence_name` добавлен в таблицу, модель, API и frontend;
- `dimension_value_ids` возвращается после создания и при последующем получении проекта;
- мастер сохраняет созданный проект поэтапно, используя существующий статус `draft` и процент
  заполненности.
- в мастере можно выбрать автора: личный профиль или активную организацию, где пользователь имеет
  роль `owner` или `maintainer`; backend проверяет членство и запрещает смену автора через обычное
  обновление проекта.

## Осталось

- вынести создание проекта, media и project-level dimensions в единую бизнес-операцию с откатом и
  очисткой файлов при ошибке;
- сделать `summary` обязательным на backend и проверять содержимое `summary` и `description`, а не
  только тип JSON;
- ограничить общий размер multipart-запроса и настроить throttle для загрузки файлов;
- определить и проверить правило выбора конечных значений иерархических dimensions;
- расширить feature-тесты сценариями прав, статусов, ролей организации, некорректных файлов,
  пустых документов и сбоев с откатом.

Отдельная модель серверного черновика не планируется. Рассмотренное решение зафиксировано как
отклонённое в [`ADR 0006: Серверные черновики создания проектов`](../adr/0006-project-creation-drafts.md).
